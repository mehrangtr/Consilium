# اجرای برنامه و ادامهٔ پژوهش

کد حاضر پایهٔ مرحلهٔ `P01` است؛ شورا و اتصال واقعی هنوز پیاده نشده‌اند. محیط دیده‌شده `Python 3.12.14` روی لینوکس است. ویندوز هدف الزامی است و نتیجهٔ بومی آن هنوز ثبت نشده است. برنامهٔ پایه برای آزمون به حساب، کلید یا اینترنت سرویس مدل نیاز ندارد.

## مسیر جاری: اجرای خودکار توسط دستیار

کاربر امکان کمک در محیط ویندوز خود را ندارد. دستیار باید اجرا، دریافت خروجی و تعمیر خطا را انجام دهد. مسیر مجاز بعدی، بارگذاری بستهٔ بررسی‌شده در مخزن عمومی متصل، پس از اجازهٔ انتشار عمومی، و اجرای گردش‌کار دو محیط است. جزئیات، مرز اجازه و معیار پذیرش در `docs/AUTOMATED_WINDOWS_FA.md` ثبت شده‌اند. دستورهای محلی زیر برای بازتولید توسط پژوهشگر دارای محیط هستند؛ تکلیف کاربر نیستند.

## آماده‌سازی لینوکس

از ریشهٔ بسته:

```bash
python3.12 -m venv .venv
.venv/bin/python -m pip install -r requirements.lock
.venv/bin/python tools/record_target_checks.py
.venv/bin/python tools/run_consilium.py mock --question "سؤال آزمایشی"
```

## آماده‌سازی ویندوز

بسته را در یک پوشهٔ تازه استخراج کنید. در خط فرمان ویندوز با `Python 3.12` نصب‌شده:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.lock
.\.venv\Scripts\python.exe tools/record_target_checks.py
```

فرمان آخر گزارش واقعی میزبان را در `evidence/targets/Windows` می‌گذارد؛ فایل `LATEST.json` به پوشهٔ اجرای ثابت با هش اشاره می‌کند. کل پوشهٔ گزارش را منتقل کنید؛ فقط متن «تست‌ها موفق شدند» کافی نیست. اگر کتابخانه، واردکردن ماژول یا دمو شکست خورد، خروجی و گزارش شکست را حفظ و علت را تعمیر کنید. اجرای ویندوز در این جلسه انجام نشده است.

گزارش ویندوز باید روی همین نسخهٔ تمام فایل‌های منبع ساخته شده باشد. پوشهٔ `evidence` و محیط مجازی وارد هش منبع نمی‌شوند. در انتقال با `Git`، فایل `.gitattributes` پایان‌خط ثابت را مشخص می‌کند. اگر منبع تغییر کند، گزارش‌های هر دو محیط برای آن نسخه دوباره لازم‌اند. از مقدار قدیمی یا ساخته‌شده به‌جای اجرای بومی استفاده نشود.

## بررسی توسعه و گیت مرحله

```text
python tools/qualityctl.py navigation
python tools/check.py
python tools/check_target_matrix.py
python tools/qualityctl.py run P01
```

فرمان `check.py` بررسی نحو، وضعیت، نماها، قالب متن، قفل محیط، آزمون کنترل و آزمون پایه را اجرا می‌کند. نتیجهٔ آن پذیرش مرحله نیست. فرمان ماتریس، شاهد بومی هر دو محیط را می‌سنجد؛ تا نبودن ویندوز، وضعیت `BLOCKED` و کد خروج `2` درست است. همین مانع اجرای پذیرش `P01` را ناموفق نگه می‌دارد. مرحلهٔ بعد آغاز نمی‌شود.

پس از دریافت هر دو شاهد معتبر، مانع رفع‌شده را با دلیل در `PROGRESS.json` ثبت، نما را تازه و بررسی پذیرش را اجرا کنید. بازبینی فعلی نهایی نیست؛ یک بازبینی تازه براساس همان معیارهای نقشه و شواهد واقعی بسازید. بازبینی توسط همان نویسنده باید همین‌گونه معرفی شود.

```text
python tools/qualityctl.py review-template P01 --out evidence/reviews/P01-final.json
python tools/qualityctl.py gate P01 --receipt evidence/runs/ACTUAL_RUN/RUN.json --review evidence/reviews/P01-final.json --commit
```

مسیر `ACTUAL_RUN` نمونه است و باید با مسیر واقعی برگردانده‌شده از `run P01` جایگزین شود. `--commit` این ابزار پیشرفت را ثبت می‌کند و ثبت نسخه در `Git` نیست. رسید، منبع، گزارش‌ها و بازبینی باید با هم سازگار باشند. وجود نقص باز یا شاهد انجام‌نشده اجازهٔ عبور نمی‌دهد.

اولین کار پس از پذیرش مرحلهٔ یک، قرارداد وضعیت و مهاجرت `SQLite`، تراکنش ثبت قصد و سپس مسیر ساختگی ثبت، شروع مجدد و خروجی پایه در `P02` است. زمان شروع آن اکنون نیست.

## تحویل نیمه‌تمام و حفظ شواهد

```text
python tools/qualityctl.py navigation
python tools/qualityctl.py handoff --out ../Consilium_Handoff_NEW.zip
python tools/qualityctl.py verify ../Consilium_Handoff_NEW.zip
```

نام آرشیو باید تازه باشد. تمام منبع و شواهد تکمیلی را در `TRANSFER_FILES.json` ثبت کنید. گزارش‌های پذیرش و آخرین اجرای مرحلهٔ جاری، حتی با شکست، منتقل می‌شوند. شواهد هر معیار هنگام پذیرش به تصویر ثابت تبدیل می‌شوند؛ فایل جاری در مرحلهٔ بعد می‌تواند تغییر کند. بازبینی اصلی محفوظ می‌ماند. پذیرش قدیمیِ مرحلهٔ صفر به همین صورت حفظ شده و دلیل آن با هش دو بازبینی در سند حفظ شواهد ثبت است؛ منبع جدید دوباره به‌عنوان مرحلهٔ صفر تأیید نشده است.

بررسی آرشیو فقط مسیر، اندازه و هش را می‌سنجد. بازتولید یعنی استخراج در پوشهٔ تازه و اجرای واقعی همین دستورها. کد و دسترسی سرویس واقعی، آزمون‌های مستقل بعدی می‌خواهند. کار نیمه‌تمام مجاز است؛ عبور از گیت ناموفق مجاز نیست.

## بازبینی دوبارهٔ پایان مرحله

در بازبینی `2026-10-06`، نصب وابستگی‌های قفل‌شده در محیط مجازی تازه و ساخت و ورود بستهٔ نصب‌شده روی لینوکس انجام شد. این شاهد، اجرای ویندوز یا بررسی نصب در همهٔ محیط‌ها نیست. خروجی‌های `build`، `dist` و `*.egg-info`، دادهٔ منبع محسوب نمی‌شوند.

ثبت‌کنندهٔ بومی اکنون گزارش‌های قابل بازنویسی قبلی را پیش از اجرا پاک می‌کند و شکست یا پایان مهلت را با گزارش تازه ثبت می‌کند. گزارش‌های ثابت قبلی باقی‌اند. ارزیاب، نتیجهٔ هر سناریو و سازگاری شمار آزمون و محیط را بررسی می‌کند؛ صرف نوشتن `PASS` کافی نیست. اجراهای هم‌زمان در یک پوشهٔ کار پشتیبانی نمی‌شوند؛ برای هر اجرا پوشهٔ مستقل داشته باشید.

## محدودیت‌های باقی‌مانده

بررسی نوع ایستا و نمایش بصری همهٔ اسناد هنوز انجام نشده است. آزمون‌های داده و اتصال ساختگی، صحت اتصال مرورگر، دوام پس از خرابی، استقلال پاسخ‌های شورای واقعی یا کیفیت پاسخ مدل را اثبات نمی‌کنند. آن موارد به ترتیب در مراحل خود آزموده می‌شوند. هدف تحویل ده‌دقیقه‌ای هنوز با پژوهشگر مستقل اندازه‌گیری نشده است.
